## Working with the mockups

`home-page-mockup.html` is **~294 MB**. Never read it whole. To inspect it, strip the embedded media first:

```bash
perl -pe 's{b64:\s*"[A-Za-z0-9+/=]{100,}"}{b64: "B64_STRIPPED"}g; s{(data:[\w/+.\-]+;base64,)[A-Za-z0-9+/=]{100,}}{$1BASE64_STRIPPED}g' home-page-mockup.html > /tmp/home.clean.html
```

That reduces it to ~40 KB / 671 lines. The two case study mockups reduce from ~12-15 MB to ~17 KB the same way.

Note the home page uses **two** embedding styles: `data:...;base64,` URIs in markup, and raw `b64: "..."` strings inside JS media objects. Strip both.

**Never extract media from the base64.** The real, full quality sources are the files in `ASSETS/`.

### Tone

Dark, minimal, editorial. Subtle procedural grain on every page. Confident, restrained motion, nothing flashy.

### Grain (implemented, `.grain` in `globals.css`)

Fixed full-viewport overlay, `pointer-events: none`, tiled 240px SVG `feTurbulence` as a data URI. No image request, no JS, one composited layer.

**The mockup's `mix-blend-mode: overlay` was silently broken and has been dropped.** Overlay against a backdrop below 50% luminance resolves to `2 x backdrop x source`. `#1F1E1F` sits near 12%, so it crushed the noise to roughly a quarter amplitude before the 5% opacity even applied, leaving nothing visible. The working version keys the noise into the **alpha channel** via `feColorMatrix` (RGB forced to white, luminance moved to alpha) and composites with **normal** blending at ~0.16 opacity. That keeps blacks from lifting into mud. Do not "restore" the overlay blend.

### Copy voice

Minimal, confident, editorial. Never salesy. **No em-dashes in prose.**

Em-dashes used as *structural separators* are fine and are kept (confirmed 2026-08-07): `Case Study — 01 / 02`, `BTS — Venice Skatepark`, `200M+ — All-Time Most Viewed Campaign`, `© 2026 — Bo Latham`. The rule targets sentence-level voice, not labels and dividers.

### The media pipeline

**`./scripts/build-media.sh` regenerates all of `public/` from `ASSETS/`.** It is the only sanctioned way to put media into the repo. Idempotent, and always encodes from the master, so re-running never stacks generation loss. Run it whenever a master changes or a new case study lands.

Encoding settings, and why:
- Every clip is a muted decorative loop, so **audio is stripped** (`-an`).
- Grid and case study video: **1280px longest side, CRF 26**. Far above what a cell a few hundred CSS pixels wide can resolve, even at 2x.
- Hero: **1920px, CRF 24**, because it runs full-bleed.
- `+faststart` so playback can begin before the file finishes downloading.
- A JPEG poster is emitted next to every clip. Homebrew's ffmpeg has **no `libwebp` encoder**, so posters are JPEG rather than WebP.

Images are copied unchanged. `next/image` runs with `unoptimized: true`, which `output: export` requires, so images are served exactly as they sit in `public/` with no resizing or format negotiation. That costs little because the masters are already cut to the exact ratios the layouts use, and it removes the `/_next/image` round trip that was a large share of the request count on Vercel.

### Rules

- **Never commit the mockup HTML files.** `home-page-mockup.html` at 294 MB exceeds GitHub's hard 100 MB per-file limit and will cause a rejected push.
- **Never commit raw video from `ASSETS/`.** Compress to derivatives first.
- `ASSETS/` stays untracked as the master source. Optimized derivatives are what enter the repo.
- `next/image` does not touch video. Video needs its own poster frames, `preload="none"`, and viewport-gated playback. The mockups autoplay every clip at once, which is fine for a local preview and not acceptable in production.

### Hosting (Cloudflare Pages, since 2026-08-17)

**Why the site left Vercel.** Vercel paused the whole `bolathams-projects` team with
`402 DEPLOYMENT_DISABLED` for exceeding the Hobby free tier: **3.19M Edge Requests against a
1M cap, and 198 GB outgoing**, over Jul 18 - Aug 17. Almost none of it was real. 99.2% of the
requests came from a single edge region (Cleveland) while Bo had told exactly two people in
Nashville the site existed. Human traffic never concentrates like that, and real usage is
about 30 visits a month. It was an automated crawler pulling the 44 MB of video repeatedly,
and there was no `robots.txt` to discourage it.

Three things made it expensive rather than merely annoying:

- Vercel serves `public/` with `max-age=0, must-revalidate`, so all ~130 media files
  revalidated on every page view. A 304 still bills as a request.
- Video is fetched in ranges, several requests per clip.
- Every `next/image` call was a separate `/_next/image` invocation.

**The setup now.** Static export (`output: export`) to plain files, deployed by the Cloudflare
GitHub app on every push to `main`. Free plan, which does not meter requests or bandwidth for
static sites, so there is no counter left to blow through.

| Setting | Value |
| --- | --- |
| Build command | `npm run build` |
| Build output directory | `out` |
| `NODE_VERSION` | `24` (build fails on the default without it) |

**Cache headers live in `public/_headers`, not `next.config.ts`.** A static export has no server,
so Next's `headers()` config is inert there and only emits build warnings; it was removed. The
`_headers` file is what Cloudflare reads. It matches media by extension rather than by directory
because `/case-studies` is both a media folder and a real route, and freezing that HTML for a
year would hide future edits from anyone who had already visited.

**Media is cached `immutable` for a year.** Filenames are stable because `build-media.sh` always
encodes from the masters to a fixed name. The tradeoff: re-cutting a clip without renaming it
leaves already-cached browsers on the old copy. Rename the file when that happens.

**Crawler policy.** `public/robots.txt` disallows `.mp4` for everyone and blocks the bulk media
scrapers by name. That is only a request, so it is backed by two Cloudflare settings on the zone:
**AI Crawl Control → Training → Block** (the default "Block on pages with ads" does nothing here,
there are no ads) and **Security → Bots → Bot Fight Mode → on**.

**Hotlink Protection is deliberately off.** It keys on the `Referer` header, so it would not have
stopped a crawler fetching files directly, and it can break `og:image` previews in Messages and
Slack, which the share-card commits exist to get right.

**Gotcha.** Cloudflare's "Retry deployment" rebuilds the commit that deployment was pinned to, so
it will replay a failure forever. Use "Create deployment", or push, to build latest. The third line
of the build log names the commit; check it before debugging anything else.

### Case study template, as built

Content lives in `src/data/case-studies.ts` as a discriminated union of row types. **Adding a case study means adding a data entry, never a new page component.** One dynamic route, `src/app/case-studies/[slug]/page.tsx`, statically generates every study via `generateStaticParams`.

```

src/app/case-studies/[slug]/page.tsx  route, generateStaticParams, metadata
src/components/case-study/
  Cell.tsx                            one media cell; --ar comes from the row
  SimilarWork.tsx                     cross-link footer card
  rows/index.tsx                      six row renderers + dispatcher
src/components/media/LazyVideo.tsx    viewport-gated playback
src/components/site/Nav.tsx           custom nav + mobile panel
src/components/site/Footer.tsx
src/styles/case-study.css             ported row/cell CSS
src/styles/site.css                   nav + footer CSS
```

Mobile reordering is data-driven: a row sets `mobileOrder: [2, 1, 0]` and each cell receives `--mobile-order`, which one CSS rule applies below 780px. No per-study CSS. Only the Bucks triptych uses it.

**Video does not autoplay on load.** `LazyVideo` uses `preload="none"` plus a poster and starts playback on IntersectionObserver, pausing off screen, and stays on the poster under `prefers-reduced-motion`. Poster frames were generated with ffmpeg as JPEG (Homebrew's ffmpeg build has no `libwebp` encoder).

**Two mockup bugs were fixed rather than reproduced**, both marked `DEVIATION` in `case-study.css`:
- `.row--text .headline` had `white-space: nowrap` releasing only at 420px, so headlines overflowed between ~421px and 780px. Now uses `text-wrap: balance`.
- Body copy used hard `<br>` tags that do not survive breakpoint changes. Copy now wraps inside the measure.

**Known cosmetic quirk, faithful to the mockups:** `.case-header__meta` is a wrapping flex row, so around 700-900px the Category block drops to a second line and keeps its left border. Same in the original. Not yet raised with Bo.

**Stat-pair tag placement differs between the two studies on purpose.** Pit Crew Chronicles renders tags in flow (top-left), Las Vegas Grand Prix pins them bottom-right. Driven by `tagPlacement`. **Confirmed deliberate by Bo 2026-08-07. Do not unify.**

`.row--text` max-width differed between mockups (90ch Red Bull, 120ch Blue Man Group). Standardized on **90ch**. Bo has not visually compared the two yet and is fine either way; revisit once the site is live if the measure reads long.
